Ferramentas e a interface agente-computador

A definição de uma ferramenta é parte do prompt. Ferramentas ruins fazem um bom modelo parecer burro. Ferramenta boa é desenhada para o agente, não espelhada da API interna.

Atualizado em 12/11 Leitura nova e exercício reescrito. Os trechos mudados aparecem marcados.

Perguntas de decisão

Leve para a sessão. No fim, você deve conseguir responder sem a fonte.

  1. 1Só pela descrição e pelos parâmetros, um dev júnior saberia usar esta ferramenta?
  2. 2Quais ferramentas leem e quais escrevem? Quais escritas não se desfazem?
  3. 3A resposta da ferramenta cabe no contexto quando o resultado é grande?

O que é novo aqui

  • Ferramentas para agentes, não para programas: uma ferramenta que resolve uma intenção (por exemplo, "agendar reunião") em vez de três chamadas de API cruas.
  • Respostas econômicas: devolver só o que importa, com paginação, filtros e um modo resumido ou detalhado. Erros que dizem ao agente o que fazer a seguir.
  • Avaliar ferramentas: rodar tarefas reais, ler as transcrições e ajustar a descrição onde o agente erra.
